## Phase 1 — MLflow: Track Your Experiment

### Why MLflow?

MLflow records every run so you can compare hyperparameters, reproduce results,
and version models. Think of it as Git for your model training.

### 1.1 Start the MLflow tracking server locally

```bash
pip install mlflow
mlflow server \
  --host 0.0.0.0 \
  --port 5000 \
  --backend-store-uri sqlite:///mlflow.db \
  --default-artifact-root ./mlruns
```

Visit **http://localhost:5000** in your browser — you'll see the MLflow UI.

### 1.2 Run the training script

```bash
# From project root, with customer_churn.csv in training/
cd training
python train.py
```

This will:
- Log `alpha`, `iterations`, `accuracy`, `final_cost` to MLflow
- Save `theta.pkl` and `scaler.pkl` to `../artifacts/`
- Register the model as **CustomerChurnModel** in the Model Registry

### 1.3 What you'll see in the MLflow UI

- **Experiments** tab → `customer-churn-prediction`
- Each run shows parameters + metrics
- **Models** tab → `CustomerChurnModel` with version history

## Phase 4 — AWS: Deploy to ECS Fargate

### Prerequisites

- AWS account with CLI configured (`aws configure`)
- Docker installed

### 4.1 Create an ECR repository

```bash
# Replace with your actual AWS account ID and preferred region
AWS_ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
AWS_REGION=us-east-1

aws ecr create-repository \
  --repository-name churn-prediction-api \
  --region $AWS_REGION
```

### 4.2 Push your image to ECR

```bash
# Login to ECR
aws ecr get-login-password --region $AWS_REGION \
  | docker login --username AWS \
    --password-stdin $AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com

# Tag the image
docker tag churn-api:latest \
  $AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/churn-prediction-api:latest

# Push
docker push \
  $AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/churn-prediction-api:latest
```

### 4.3 Create an ECS Cluster

```bash
aws ecs create-cluster --cluster-name churn-cluster
```

### 4.4 Create the Task Definition (save as task-definition.json)

```json
{
  "family": "churn-task",
  "networkMode": "awsvpc",
  "requiresCompatibilities": ["FARGATE"],
  "cpu": "256",
  "memory": "512",
  "executionRoleArn": "arn:aws:iam::YOUR_ACCOUNT_ID:role/ecsTaskExecutionRole",
  "containerDefinitions": [
    {
      "name": "churn-api",
      "image": "YOUR_ACCOUNT_ID.dkr.ecr.us-east-1.amazonaws.com/churn-prediction-api:latest",
      "portMappings": [{"containerPort": 8000, "protocol": "tcp"}],
      "essential": true,
      "logConfiguration": {
        "logDriver": "awslogs",
        "options": {
          "awslogs-group":         "/ecs/churn-api",
          "awslogs-region":        "us-east-1",
          "awslogs-stream-prefix": "ecs"
        }
      },
      "healthCheck": {
        "command": ["CMD-SHELL", "curl -f http://localhost:8000/health || exit 1"],
        "interval": 30,
        "timeout":  10,
        "retries":  3
      }
    }
  ]
}
```

Register it:
```bash
aws ecs register-task-definition --cli-input-json file://task-definition.json
```

### 4.5 Create an ECS Service

```bash
# First create a Security Group that allows inbound TCP on port 8000
SG_ID=$(aws ec2 create-security-group \
  --group-name churn-api-sg \
  --description "Churn API security group" \
  --query GroupId --output text)

aws ec2 authorize-security-group-ingress \
  --group-id $SG_ID \
  --protocol tcp \
  --port 8000 \
  --cidr 0.0.0.0/0

# Get a public subnet ID from your default VPC
SUBNET_ID=$(aws ec2 describe-subnets \
  --filters "Name=default-for-az,Values=true" \
  --query "Subnets[0].SubnetId" --output text)

# Create service
aws ecs create-service \
  --cluster churn-cluster \
  --service-name churn-service \
  --task-definition churn-task \
  --desired-count 1 \
  --launch-type FARGATE \
  --network-configuration "awsvpcConfiguration={
    subnets=[$SUBNET_ID],
    securityGroups=[$SG_ID],
    assignPublicIp=ENABLED
  }"
```

### 4.6 Get the public IP

```bash
# Get the task ARN
TASK_ARN=$(aws ecs list-tasks \
  --cluster churn-cluster \
  --query "taskArns[0]" --output text)

# Get the ENI (network interface) attached to the task
ENI_ID=$(aws ecs describe-tasks \
  --cluster churn-cluster \
  --tasks $TASK_ARN \
  --query "tasks[0].attachments[0].details[?name=='networkInterfaceId'].value" \
  --output text)

# Get the public IP
aws ec2 describe-network-interfaces \
  --network-interface-ids $ENI_ID \
  --query "NetworkInterfaces[0].Association.PublicIp" \
  --output text
```

Your API is now live at `http://<PUBLIC_IP>:8000/docs` 🎉

## Phase 5 — CI/CD with GitHub Actions (Automatic Deploys)

### 5.1 Add GitHub Secrets

In your repo: **Settings → Secrets and variables → Actions → New secret**

| Secret Name             | Value                         |
|-------------------------|-------------------------------|
| `AWS_ACCESS_KEY_ID`     | Your IAM user access key      |
| `AWS_SECRET_ACCESS_KEY` | Your IAM user secret key      |

> Create an IAM user with `AmazonECR_FullAccess` + `AmazonECS_FullAccess` policies.

### 5.2 Push to main → auto deploys

```bash
git add .
git commit -m "feat: update churn model"
git push origin main
```

The pipeline in `.github/workflows/deploy.yml` will:
1. Build your Docker image
2. Push to ECR (tagged with commit SHA + `latest`)
3. Update the ECS task definition
4. Roll out a new deployment with zero downtime

## Cost Estimate (AWS Free Tier Friendly)

| Service         | Usage              | Estimated Cost      |
|-----------------|--------------------|---------------------|
| ECR             | ~50 MB image       | ~$0.005/month       |
| ECS Fargate     | 256 CPU / 512 MB   | ~$10–15/month       |
| CloudWatch Logs | Basic logging      | Free tier           |
| Data Transfer   | Low traffic        | Free tier           |
| **Total**       |                    | **~$10–15/month**   |

> **Tip:** Stop the ECS service when not in use to save costs:
> `aws ecs update-service --cluster churn-cluster --service churn-service --desired-count 0`
